# Virtual X Platform tools and methods

Template for the folder that defines the **tools** (services) and **methods**
shown on a Virtual X Platform. It is derived from the
[VHP4Safety cloud repository](https://github.com/VHP4Safety/cloud) and ships with
demo content: one demo tool and one demo method.

The folder has two outputs:

* a catalog website, served by GitHub Pages from [`docs/`](docs), as part of the website of the repository, at `https://YOUR-ORG.github.io/virtual-x-platform-config/cloud/`
* two index files that the platform reads: [`cap/service_index.json`](cap/service_index.json)
  and [`cap/methods_index.json`](cap/methods_index.json)

The platform reads the tools and methods **once**, when it is launched, and stores them as records. After the
launch, tools and methods are changed in the record editor of the platform; this folder stays the place where
users request new tools and methods (the issue forms), and its catalog website stays available.

## Make it yours

1. Replace `YOUR-ORG` everywhere with your GitHub organization (see the tutorial in the template root).
2. Edit the intro and outro texts of the catalog pages in [`misc/workflow_in_r/`](misc/workflow_in_r).
3. Replace the demo tool and method with your own (see below).
4. Update the options in the issue forms `new-tool-service-entry.yml` and `new-tool-method-entry.yml` in
   [`.github/ISSUE_TEMPLATE/`](../.github/ISSUE_TEMPLATE) of the repository:
   the use cases, use case questions, and workflow stages of your platform.
5. Set up GitHub Pages and the GitHub Actions of the repository, see the [README of the repository](../README.md).

## Adding a tool

* copy [`docs/service/template.json`](docs/service/template.json) to `docs/service/<id>.json`
  and fill it in; see [`docs/service/demo_tool.json`](docs/service/demo_tool.json) for an example
* optionally add a screenshot or logo as `docs/service/<id>.png` and name it in the `screenshot` field
* commit and push; the Markdown page, the catalog pages, the index, and `sitemap.xml` are generated by GitHub Actions

Do not remove `template.json`. Users without write access can request a tool with the
*New Service Catalogue Entry* issue form.

Three fields connect a tool to the glossary, the use cases and the platform:

| Field | Meaning |
|---|---|
| `stage` | IRI of a *Process Flow Step* in the glossary, e.g. `https://YOUR-ORG.github.io/virtual-x-platform-config/glossary#VXP0000005` |
| `regulatory-question` | the use case questions the tool is relevant for; the keys (e.g. `1a`) are the codes of the questions, mapped to their addresses in `linkeddata/launch/casestudies.yaml` of the platform |
| `instance.platform` | `development` or `production` when the tool is hosted by the project, `external` otherwise |

## Adding a method

* post an issue with the *New Method Catalogue Entry* form
* for maintainers: add a label containing `method` (e.g. `method-approved-for-pr`) when the request looks right;
  a GitHub Action then opens a pull request with `docs/methods/<id>.json`
* merge the pull request; the Markdown page and the indexes are generated by GitHub Actions

See [`docs/methods/demo_method.json`](docs/methods/demo_method.json) for an example.
The keys of the method JSON are derived from the labels in the issue form.

## What is generated

| Output | From | Generated by | GitHub Action |
|---|---|---|---|
| `docs/service/<id>.md`, `docs/index.md`, `docs/catalog.md`, `docs/tools.tsv`, `docs/sitemap.xml` | `docs/service/*.json` | R scripts in `misc/workflow_in_r/` | `create-markdown-v2.yml` |
| `cap/service_index.json` | `docs/service/*.json` | `misc/generate_service_metadata.py` | `generate_service_index.yml` |
| `docs/methods/<id>.json` | issue form | inline Python | `create_method_json_pr.yml` |
| `docs/methods/<id>.md` | `docs/methods/*.json` + `method_template.md` | mustache | `generate_method_markdown.yml` |
| `docs/methods/index.md` | `docs/methods/*.json` | inline Python | `generate_method_markdown_index.yml` |
| `cap/methods_index.json` | `docs/methods/*.json` | `misc/generate_methods_metadata.py` | `generate_method_index.yml` |
| the website | `docs/` | Jekyll | `jekyll-gh-pages.yml` |

To generate the files locally (needs Python, R with the rjson package, and mustache):

```shell
python3 misc/generate_service_metadata.py
python3 misc/generate_methods_metadata.py
(cd misc/workflow_in_r && Rscript create_sitemap.r && Rscript workflow_rscript.r)
mustache docs/methods/demo_method.json method_template.md > docs/methods/demo_method.md
```

### Bioschemas annotation

The Markdown page of a tool includes autogenerated [Bioschemas](https://bioschemas.org/) annotation:

```json
{
  "@context": "https://schema.org/",
  "@type": "SoftwareApplication",
  "http://purl.org/dc/terms/conformsTo": {
      "@type": "CreativeWork", "@id": "https://bioschemas.org/profiles/ComputationalTool/1.0-RELEASE"
  },
  "@id" : "https://YOUR-ORG.github.io/virtual-x-platform-config/cloud/service/demo_tool",
  "name": "Demo Tool",
  "description": "A demo tool to show how tools are listed in the Virtual X Platform.",
  "url": "https://example.org/demo-tool"
}
```
